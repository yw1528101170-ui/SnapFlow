# SnapFlow 密码库 - 浏览器扩展（手动加载开发版）

MV3 纯 JS，无构建链。Chromium 系（Chrome / Edge）可用；Firefox 的原生消息清单结构不同，暂不支持。

## 安装与关联（一次性）

1. 启动 SnapFlow 桌面端，打开「设置 → 密码库」。
2. 浏览器打开扩展管理页（`chrome://extensions` 或 `edge://extensions`），开启「开发者模式」→「加载解压缩的扩展」→ 选择本目录（`ext/snapflow-vault`）。
3. 复制扩展卡片上的 **ID**，粘贴到 SnapFlow「设置 → 密码库 → 浏览器自动填充」的扩展 ID 框，点「启用」。
4. 打开任意登录页，点浏览器工具栏上的 SnapFlow 图标：
   - 首次连接时桌面端会弹出**关联确认**，点「是」完成配对（扩展令牌的哈希存入密码库，令牌原文不出扩展）。
5. 解锁密码库（Alt+P）后，popup 即列出当前站点匹配的条目，点「填充」自动写入表单。

## 安全模型

- 通信链路：扩展 →（原生消息 stdio）→ `SnapFlow.exe --native-messaging` →（本机命名管道，ACL 限当前用户）→ 桌面端。
- 准入：扩展首次连接需桌面端人工确认；此后每条请求携带令牌、桌面端比对令牌 SHA-256。
- `get-logins` 仅在**库已解锁**时返回凭据；锁定时 popup 引导用户解锁。
- 浏览器扩展存储只保存随机令牌（不是凭据）；凭据仅在填充瞬间存在于页面。

## 手动测试清单

- [ ] 桌面端未运行时打开 popup → 显示「未连接」与排查提示（宿主报 `app-not-running`）。
- [ ] 设置页未启用集成 → 显示「未启用」。
- [ ] 首次连接 → 桌面端弹关联确认；拒绝 → popup 显示「未关联」；允许 → 正常列出条目。
- [ ] 库锁定 → popup 显示「已锁定」，无条目泄露；Alt+P 解锁后重试成功。
- [ ] GitHub 登录页：匹配 `github.com` 条目；`api.github.com` 页面也能匹配（子域）；`notgithub.com` 不匹配。
- [ ] 填充：用户名 + 密码正确写入 React/Vue 站点的受控输入框（input 事件已派发）；用户名落在密码框上方最近的文本框（或 autocomplete="username" 的输入框），不会误填页面底部的搜索框。
- [ ] 生成器：随机密码 16 位 / 密码短语 6 词，复制可用。
- [ ] 桌面端长时间无响应（挂起模拟）→ popup 各请求 10 秒超时后显示「未连接」。
- [ ] 内容脚本不在的页面（扩展安装前已打开的标签）点「填充」→ 按钮显示「失败」并给出刷新提示，而不是无声卡住。
- [ ] 托盘「锁定密码库」后立即在浏览器请求 → 已锁定。
- [ ] 禁用集成（设置页）后 → popup 显示「未启用」。
